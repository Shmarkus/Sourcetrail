# `st` Trust and Speed (Phase 2.5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `st` fast enough after an edit and honest about what it can't see. Then check, on unseen questions and without prompting, that agents get correct answers and choose `st` on their own.

**Architecture:**
- Delombok runs only on changed original files (resolving against the full source roots), and falls back to the whole tree when it must.
- Graph queries count the index gaps they touch and report them in one stderr line.
- `filter` exits 3 on unknown keys.
- Two agent evaluations (holdout questions, unprompted use) are documented next to the Phase 2 benchmark.

**Tech Stack:** C++17, Qt5, Catch2, Lombok delombok via the Java bridge, Bash smoke tests, subagent evaluations.

**Spec:** `docs/superpowers/specs/2026-10-30-sourcetrail-cli-requirements.md`.

Background:
- Phase 2 plan: `docs/superpowers/plans/2026-10-31-st-architecture.md`.
- Benchmark: `docs/superpowers/specs/2026-10-31-st-benchmark-results.md`.
- Review feedback that motivates this plan: the 19 s refresh, a holdout question set, warnings about blind spots instead of silent gaps, reversing ruling R2, and testing unprompted use.

## Global Constraints

- Everything in the Phase 1 and Phase 2 Global Constraints still holds: output format, exit codes, stdout only for results, "never a wrong original line".
- Changed-files refresh: target under 5 s for a few changed files (spec). Measure on the shop scratch copy.
- A warning never changes stdout or the exit code. It is one stderr line, starting `st: incomplete:`.
- Never modify `/home/markus/Projects`. Real-project work uses the scratch copies under the session scratchpad (`.../scratchpad/real/shop-src`, `.../batch-src`).

## Review Focus

1. **Equivalence:** incremental delombok output for a changed file must be byte-identical to a full delombok run of the same tree. Test: Task 1 `incremental delombok matches a full run` (fixture plus shop spot check).
2. **Deleted or renamed originals:** the delombok copy must disappear, and the index must drop the file. Test: Task 1 smoke step.
3. **Edits to `lombok.config` or a build file:** these force a whole-tree delombok. Test: Task 1 unit test.
4. **Results that touch no gap:** no warning line. That keeps the warning meaningful. Test: Task 3 `no incomplete line when nothing is missing`.
5. **A typo in a `filter` key exits 3,** even when other lines pass. Test: Task 2.

### Task 1: Delombok only what changed

**Files:** `src/lib_java/utility/utilityGradle.{h,cpp}` (`runDelombok` and its callers), `src/lib_java/utility/utilityGradleCache.{h,cpp}` (manifest), tests in `src/test/GradleCacheTestSuite.cpp` / `src/test/DirectorySyncTestSuite.cpp`, `testing/cli/st-smoke.sh`.

- [ ] **Step 1: Spike first, and report before building.**
  - On the shop scratch copy, time delombok of the whole `main` set, then of one file. For the single file, pass that file as input, all of the set's source roots as `--sourcepath`, and the same classpath and `-f` options.
  - Check that the output is byte-identical to the full run's copy of that file.
  - If it isn't identical, or isn't faster, stop and report BLOCKED with the numbers.
- [ ] **Step 2: Manifest.** Next to each `delombok/<set>` output, store `<original relpath>\t<size>\t<mtime ns>` for every original file of the set.
- [ ] **Step 3: Incremental run.** For each set:
  - Compare the originals against the manifest.
  - When nothing changed, skip delombok.
  - When only some files changed or were added, delombok exactly those files into the temp dir (with the full sourcepath) and sync only those outputs.
  - For removed originals, delete their outputs.
  - Do a whole-tree run when the manifest is missing or unreadable, when any `lombok.config` in the roots changed, or when the Gradle build fingerprint changed.
  - Write the manifest only after a successful run.
- [ ] **Step 4: Tests,** each RED first:
  - `incremental delombok matches a full run` (fixture);
  - `delombok runs on the whole tree when lombok.config changes`;
  - `delombok removes the copy of a deleted original`;
  - manifest round trip.
  - Smoke: edit one fixture file and check that only that file is re-indexed; delete one and check that its symbols disappear.
- [ ] **Step 5: Measure on the shop scratch copy.** Run a one-file edit followed by `st callers ...`, three times. Report the refresh times (target under 5 s) and the split between Gradle, delombok and indexing.
- [ ] **Step 6: Run the full `Sourcetrail_test`** against the baseline, plus both smoke scripts. Commit `perf(gradle): delombok only changed files`.

### Task 1b: Re-index only the files an edit can affect

Added after Task 1 measured it. delombok is now about 0.45 s, but the same one-line edit on shop re-indexed 8, 166 and 252 dependent files across three runs, giving refreshes of 7–16 s.

**Files:** `src/lib/project/Project.cpp`, `src/lib/project/RefreshInfoGenerator.cpp` and `src/lib/data/storage/PersistentStorage.cpp` (`getReferencing*`) as needed, plus tests in `src/test/`.

- [ ] **Step 1: Find out why the count varies,** with evidence: the exact file set chosen per run and which rule added each file (direct importers, symbol references, incomplete or error files, files whose mtime changed). Report before changing code if the cause is outside the indexer, for example timestamps touched by delombok or Gradle.
- [ ] **Step 2: Re-index referencing files only when the edit changes what the file declares.**
  - First index the changed files.
  - Compare their declared symbols (name + signature + kind) with what the index had before.
  - Only when declarations were added, removed or changed, index the files that reference the changed or removed declarations.
  - A body-only edit therefore re-indexes one file.
  - The Phase 1 guarantee stays: when a signature changes, callers in unedited files are still found. The existing test "storage finds files referencing symbols declared in changed files without imports" and a new test pin this.
- [ ] **Step 3: Measure on shop.** Three runs of a body-only edit (target: total refresh under 5 s), and one run of a signature change, whose callers must stay correct. Report the time split.
- [ ] **Step 4: Run the full `Sourcetrail_test`** against the baseline, plus both smoke scripts. Commit `perf(index): re-index referencing files only when declarations change`.

### Task 3: Warn when an answer touches a blind spot of the index

**Files:** `src/cli/st/StGraph.cpp`, `StArchitecture.cpp`, `StMain.cpp`, `StOutput.{h,cpp}` (or a small `StGaps.{h,cpp}`), `PersistentStorage.{h,cpp}` if an accessor is needed, tests in `StQueryTest.cpp`, `README.md`.

- [ ] **Define the gaps, per command.** The walked set is the inputs plus every node reached.
  - **Unresolved links:** links between a walked node and a node that is `unsolved-symbol`, or whose kind is unknown (`NODE_SYMBOL`), or that is non-indexed but has a name in the project's own packages. Records and generated sources look like this.
  - **Files with index errors:** files with errors (`getErrorInfos` / incomplete files) that hold a walked node's definition or a result location.
- [ ] **Print one line** when either count is above zero: `st: incomplete: <n> links to unresolved symbols, <m> files with index errors (see st status)`. Leave out a part that is zero. This applies to `callers`, `callees`, `refs`, `impact`, `path`, `deps`, `impls` and `supers`. stdout and exit codes stay unchanged.
- [ ] **`st status`** adds the totals: unresolved symbols and files with errors.
- [ ] **Tests,** RED first:
  - callers of a method also called from an unresolved node warns, and the count is right;
  - a result in a file with an error warns;
  - `no incomplete line when nothing is missing`.
- [ ] **Real-index check:**
  - On batch, callers of a method used inside a Java record (`Result`'s records) warns.
  - On shop, a query touching JPA metamodel users (e.g. `refs` of a repository method using `Catalog_`) warns.
  - A clean query prints no line.

  Paste the outputs into the report. Commit `feat(st): warn when an answer touches a gap in the index`.
